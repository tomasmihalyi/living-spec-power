# Living Spec Adoption Playbook

## Pilot Program (suggested: 1-2 weeks)

| Step | Action | Success Criteria |
|------|--------|------------------|
| 1 | Select 1 project, 2-3 developers | Team willing to try |
| 2 | Use Option A (Living Spec Only) | Simplest approach |
| 3 | Create spec together in first session | Spec created in <30 min |
| 4 | Use for 1-2 weeks | Updated 3+ times organically |

## Expansion (suggested: 2-4 weeks after pilot)

1. Add 2-3 more projects based on pilot feedback
2. Identify champion per team (person who "gets it")
3. Collect friction points and address
4. Consider Option B for complex projects

## Full Rollout

| Phase | Action |
|-------|--------|
| Default | New projects start with Living Spec |
| Optional | Existing projects can adopt (brownfield scan available) |
| Review | Monthly check on adoption metrics |

## Common Objections & Responses

| Objection | Response |
|-----------|----------|
| "Another doc to maintain" | AI maintains it; you just approve changes |
| "We have Confluence/Notion" | Living Spec consolidates active work; archive old docs |
| "Too much overhead" | Option A: 3-5 questions, <30 min setup |
| "Devs won't use it" | It's in Kiro IDE where they already work |
| "What about existing specs?" | Brownfield scan auto-populates from codebase |

## Adoption Metrics

Track weekly:
- Specs created vs projects started
- Average updates per spec per week
- Time from project start to spec creation
- Developer satisfaction (quick survey)
