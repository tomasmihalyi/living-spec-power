# Living Spec Maintenance Steering Template

This template is used to create a project-specific steering file that ensures the Living Spec stays up-to-date as the single source of truth.

## When to Create

On first activation of the Living Specs power in a project, create this steering file at `.kiro/steering/living-spec-maintenance.md` with project-specific details filled in.

## Template

```markdown
---
inclusion: always
---

# Living Spec Maintenance

This steering file ensures the Living Spec stays up-to-date as the single source of truth for this project.

## Single Source of Truth

**Living Spec Location**: `.kiro/specs/00-{{PROJECT_NAME}}.living.md`

This file is the authoritative source for:
- Project intent and goals
- Requirements and architecture decisions
- Implementation progress and metrics
- Decision history and next actions

## When to Update the Living Spec

Update the Living Spec when any of the following occur:

### Task Completion
- ✅ Completing a task or task group
- ✅ Finishing an execution plan stage

### Spec Changes
- ✅ Creating a new Kiro spec
- ✅ Kiro spec phase changes (🔵 → 🟢 → 🟡)

### Decisions & Scope
- ✅ Making an architecture decision
- ✅ Changing project scope (in/out of scope)
- ✅ Changing priorities or next actions

### Phase Transitions
- ✅ Completing a phase (Planning → Building → Operating)
- ✅ Adding technical debt items

## Update Format

### Timestamps
- Always update `Last Updated` in header with ISO format: `YYYY-MM-DDTHH:MM:SSZ`
- Example: `2026-01-08T14:30:00Z`

### Status Markers
| Marker | Meaning |
|--------|---------|
| ⬚ | Not started |
| 🔄 | In progress |
| ✅ | Complete |

### Phase Markers
| Marker | Phase |
|--------|-------|
| 🔵 | Planning |
| 🟢 | Building |
| 🟡 | Operating |

### Decision Log Entries
Always include:
- ISO timestamp
- Phase context (🔵/🟢/🟡)
- Decision summary
- Approval status

## Self-Prompt Reminder

> **After completing any work, ask yourself:**
> "Should I update the Living Spec to reflect this change?"

## What to Update After Completing Work

### Current Status Section
- **Next Action**: Update to reflect what comes next
- **Last Completed**: Update with what was just finished
- **Blockers**: Add or remove as appropriate

### Execution Plan
- Update stage status (⬚ → 🔄 → ✅)
- Add duration if completed

### Related Kiro Specs
- Add new specs when created
- Update phase when spec progresses:
  - 🔵 Planning → 🟢 Building (when moving to tasks.md)
  - 🟢 Building → 🟡 Operating (when deployed)

### Decision Log
- Add entry for any significant decision
- Include timestamp, phase, context, approval

### Next Actions
- Move completed items to Completed section
- Reprioritize remaining items
- Add new items discovered during work

## Current Spec Hierarchy

{{SPEC_HIERARCHY}}

## Project Strategy & Roadmap

{{PROJECT_STRATEGY}}

---

*This steering file was auto-generated by the Living Specs power. Update the spec hierarchy and strategy sections as the project evolves.*
```

## Placeholder Definitions

When creating the steering file, replace these placeholders:

| Placeholder | Source | Example |
|-------------|--------|---------|
| `{{PROJECT_NAME}}` | Living Spec filename | `project`, `my-app` |
| `{{SPEC_HIERARCHY}}` | Related Kiro Specs table from Living Spec | See below |
| `{{PROJECT_STRATEGY}}` | Intent section from Living Spec | See below |

### Spec Hierarchy Format

```markdown
| Spec | Path | Phase | Description |
|------|------|-------|-------------|
| Project | `.kiro/specs/00-project.living.md` | 🟢 Building | Main orchestrator |
| Auth | `.kiro/specs/auth/` | 🔵 Planning | User authentication |
| Payments | `.kiro/specs/payments/` | ⬚ Not started | Payment processing |
```

### Project Strategy Format

```markdown
**Problem**: [From Intent section]
**Hypothesis**: [From Hypothesis table if present]
**Success Criteria**: [From Success Criteria table]
**Current Phase**: [From header]
**Current Focus**: [From Next Actions]
```
